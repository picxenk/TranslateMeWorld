# TranslateMeWorld

한국어·영어 원문을 로컬 Ollama로 번역하고, 앱에 등록된 56개 언어의 결과를 78개 국가 마커에서 탐색하는 앱입니다. HTML/CSS/vanilla JavaScript가 `index.html` 하나에 들어가며 CDN, 빌드, 별도 애플리케이션 백엔드가 필요 없습니다. 지도는 이해를 돕는 단순화된 그림이며 실제 국경이나 언어 분포의 공식 자료가 아닙니다.

## 언어와 지역 범위

앱의 번역 대상은 기존 52개 언어에 암하라어(`am`), 하우사어(`ha`), 요루바어(`yo`), 이그보어(`ig`)를 더한 **서로 다른 56개 언어**입니다. 이 네 언어는 실험적 추가 대상으로, 지도·저장 기록 팝업에서 모델이 다른 언어로 응답할 수 있음을 안내합니다. 실제 로컬 모델의 간단한 점검에서도 요루바어·이그보어 요청에 다른 언어의 문자가 출력되었습니다. 새 언어의 품질은 보장하지 않으며 **Google에서 원문 번역** 버튼으로 원문을 해당 언어로 다시 번역해 확인할 수 있습니다. [TranslateGemma 공식 모델 카드](https://huggingface.co/google/translategemma-4b-it)는 55개 언어를 명시하지만, 그 정확한 목록과 앱 목록의 일치 여부는 확인하지 않았습니다. 앱의 56개 대상 수는 모델의 공식 지원 수나 번역 품질 검증을 뜻하지 않습니다.

국가 마커는 총 78개이며, 북미 14개(중앙아메리카·카리브해 포함), 남미 12개, 아프리카 10개를 포함합니다. 화면의 언어·국가 수와 번역 진행 수는 데이터에서 동적으로 계산합니다. 아래는 현재 앱에 연결한 국가와 언어이며, 해당 지역의 언어 분포를 빠짐없이 나열한 표가 아닙니다.

### 아프리카

요청된 여섯 언어의 지도 연결은 다음과 같습니다. 기존 아프리칸스어(`af`)도 남아프리카공화국에서 계속 선택할 수 있습니다.

| 언어 | 앱에서 연결한 국가 | 구분 |
| --- | --- | --- |
| 암하라어 (`am`) | 에티오피아 | 실험적 추가 |
| 스와힐리어 (`sw`) | 케냐, 탄자니아, 우간다, 콩고민주공화국 | 기존 언어, 국가 확장 |
| 하우사어 (`ha`) | 나이지리아, 니제르, 가나 | 실험적 추가 |
| 요루바어 (`yo`) | 나이지리아, 베냉 | 실험적 추가 |
| 이그보어 (`ig`) | 나이지리아 | 실험적 추가 |
| 줄루어 (`zu`) | 남아프리카공화국 | 기존 언어 |

### 아메리카

주요 언어를 다음과 같이 연결하며, 같은 언어는 여러 국가에서 동일한 번역 결과를 공유합니다.

| 지역 | 앱에서 연결한 국가 | 언어 |
| --- | --- | --- |
| 북미 | 미국, 벨리즈 | 영어 (`en`), 스페인어 (`es`) |
| 북미 | 캐나다 | 영어 (`en`), 프랑스어 (`fr`) |
| 북미 | 멕시코, 과테말라, 온두라스, 엘살바도르, 니카라과, 코스타리카, 파나마, 쿠바, 도미니카공화국 | 스페인어 (`es`) |
| 북미 | 자메이카 | 영어 (`en`) |
| 북미 | 아이티 | 프랑스어 (`fr`) |
| 남미 | 브라질 | 포르투갈어 (`pt`) |
| 남미 | 아르헨티나, 칠레, 페루, 콜롬비아, 베네수엘라, 에콰도르, 볼리비아, 파라과이, 우루과이 | 스페인어 (`es`) |
| 남미 | 가이아나 | 영어 (`en`) |
| 남미 | 수리남 | 네덜란드어 (`nl`) |

표의 연결은 국가의 유일한 언어 또는 주된 모어라는 뜻이 아닙니다. 예를 들어 아이티의 프랑스어 표시는 아이티 크레올어를 대신하거나 프랑스어가 주된 모어라는 의미가 아닙니다. 아메리카의 토착어와 크레올어는 현재 별도 대상으로 열거하지 않으며, 아프리카를 포함한 각국의 다른 언어도 모두 망라하지 않습니다. 번역문 자체에는 국가별 방언·지역 표현 차이를 반영하지 않습니다.

## 실행

1. [Ollama](https://ollama.com)를 설치하고 실행한 뒤 모델을 내려받습니다.

```bash
ollama pull translategemma:4b
```

2. `index.html` 파일을 브라우저에서 직접 엽니다. 별도 웹 서버는 필요하지 않습니다.

브라우저가 로컬 파일의 API 요청을 제한한다면 정적 서버를 대신 사용할 수 있습니다.

```bash
python3 -m http.server 8000
```

이 경우 브라우저에서 <http://localhost:8000>을 엽니다.

기본 API 주소는 `http://localhost:11434`입니다. 기본 모델은 `translategemma:4b`이며, 없으면 설치된 다른 `translategemma` 계열 모델을 사용합니다.

## 사용

- 한국어 또는 영어를 입력합니다. 자동 감지는 한글이 있으면 한국어, 없으면 영어로 판단하며, 원문 언어를 직접 선택할 수도 있습니다.
- 번역 버튼 또는 `Ctrl + Enter` / `Cmd + Enter`로 시작합니다. 언어별로 순차 요청하며 완료된 결과부터 지도에 링크가 표시됩니다. 원문 언어는 요청 없이 표시하며, 같은 언어를 사용하는 국가마다 API를 중복 호출하지 않습니다.
- 유럽처럼 밀집된 지역이나 모바일에서는 세계 전체·북미·남미·유럽·아시아·아프리카 탭으로 탐색합니다. 좁은 화면에서는 좌우로 스크롤할 수 있고, 지도 높이는 마커를 배치할 공간이 부족하면 늘어납니다. 인도·남아프리카공화국·나이지리아처럼 여러 언어가 묶인 국가에서는 개별 언어를 선택합니다.
- 결과 팝업에서 개별 번역을 저장합니다. 저장 목록에는 원문, 번역문, 원문·대상 언어와 선택한 국가가 포함되며 중복 저장 방지와 삭제를 지원합니다. 원문·원문 언어·대상 언어·번역문이 같으면 다른 국가에서 선택해도 중복 저장하지 않고 처음 저장한 국가를 유지합니다. 국가 정보가 없는 예전 기록은 불러올 때 해당 언어의 기존 대표 국가로 보정합니다.
- 팝업의 **듣기** 버튼으로 번역을 읽어줍니다. 재생 중에는 **중지**로 바뀌며, 다른 번역을 재생하거나 팝업을 닫으면 기존 음성이 멈춥니다. 저장된 히스토리도 팝업을 열어 들을 수 있습니다.
- **Google 번역에서 듣기** 버튼은 해당 번역문과 언어를 설정한 Google 번역 페이지를 새 탭으로 엽니다. 새 탭 입력란의 스피커 버튼을 눌러 들으세요. 로컬 음성 지원 여부와 관계없이 사용할 수 있지만, Google의 음성 지원 여부는 언어마다 다릅니다. 클릭 시 해당 번역문이 Google에 전달되고 기존 로컬 음성 재생은 중지됩니다.
- 실험적 추가 언어에는 **Google에서 원문 번역** 버튼도 표시됩니다. 원문이 있으면 로컬 번역 대기 중이거나 실패한 경우에도 사용할 수 있으며, 원문과 대상 언어를 설정한 새 탭을 엽니다. 자동으로 외부 번역을 호출하거나 결과를 가져오지는 않습니다.
- 입력이나 원문 언어를 바꾸면 진행 중인 요청과 대기열을 취소합니다. 새 번역은 다시 버튼/단축키로 시작하며, 실패한 결과는 오류 안내에 따라 재시도합니다.

## 음성 지원

브라우저 내장 Web Speech API를 사용하며 별도 TTS 서버나 API 키가 필요 없습니다. 브라우저가 `localService: true`로 보고하는 해당 언어의 로컬 음성만 선택합니다. 선택한 국가(저장 기록에서는 저장된 국가)의 로케일을 우선하고, 없으면 같은 언어의 다른 로컬 음성을 사용하며 온라인 음성이나 다른 언어로 대신 읽지 않습니다. 이 우선순위는 읽어주는 음성에만 적용되며 번역문은 국가 간 공유됩니다.

지원 여부와 목소리는 운영체제·브라우저·설치된 음성에 따라 달라지므로 앱의 56개 언어 모두의 음성을 보장하지 않습니다. 로컬 음성이 없거나 브라우저가 API를 지원하지 않으면 듣기 버튼이 비활성화되고 이유가 표시됩니다. 필요한 언어의 음성을 운영체제 설정에서 설치한 뒤 브라우저를 다시 열어보세요. 설치 과정에는 다운로드가 필요할 수 있습니다. 음성 목록이 늦게 준비되는 경우에는 버튼 상태가 자동으로 갱신됩니다.

## 연결 문제

Ollama 실행 여부와 모델 설치를 먼저 확인하세요. 터미널로 서버를 실행한다면 `ollama serve`를 사용합니다. 이미 Ollama 앱이 실행 중이면 서버를 중복 실행하지 마세요.

서버 없이 `index.html`을 직접 열었을 때 브라우저 콘솔에 CORS 오류가 있으면 `OLLAMA_ORIGINS`를 `*`로 설정합니다. `*`는 모든 Origin을 허용하므로 신뢰할 수 있는 로컬 환경에서만 사용하세요.

macOS에서는 Ollama 앱을 완전히 종료하고 터미널에서 다음 명령을 실행한 뒤 Ollama 앱을 다시 엽니다.

```bash
launchctl setenv OLLAMA_ORIGINS "*"
```

Windows에서는 작업 표시줄의 Ollama 아이콘을 눌러 앱을 종료한 뒤 다음 순서로 설정합니다.

1. Windows 설정 또는 제어판에서 `환경 변수`를 검색합니다.
2. **사용자 환경 변수 편집**에서 이름이 `OLLAMA_ORIGINS`, 값이 `*`인 변수를 추가합니다.
3. 적용한 뒤 시작 메뉴에서 Ollama를 다시 실행합니다.

명령 프롬프트에서는 사용자 환경 변수를 다음과 같이 추가할 수도 있습니다. 명령 실행 후 Ollama를 다시 시작해야 적용됩니다.

```bat
setx OLLAMA_ORIGINS "*"
```

터미널에서 `ollama serve`를 직접 실행할 때는 해당 프로세스에 환경 변수를 전달할 수도 있습니다.

```bash
OLLAMA_ORIGINS="*" ollama serve
```

정적 서버를 사용한다면 `*` 대신 실제 페이지 Origin(예: `http://localhost:8000`)만 허용하는 편이 안전합니다. 연결 실패만으로 CORS 문제라고 단정할 수는 없습니다.

## 저장과 개인정보

기본 설정에서 번역 요청은 로컬 Ollama로만 전달되며 외부 번역 서비스로 전송되지 않습니다. 직접 저장한 번역은 해당 브라우저·사이트 origin의 `localStorage`에 남습니다. 앱에서 암호화하지 않으므로 공용 기기에서는 민감한 내용을 저장하지 마세요. 계정 동기화나 클라우드 백업은 없으며, 저장 목록에서 삭제하거나 사이트 데이터를 지우면 제거됩니다. 다른 브라우저나 호스트·포트에서는 같은 저장 목록을 볼 수 없습니다.

단, **Google 번역에서 듣기**를 직접 누르면 선택한 번역문이, **Google에서 원문 번역**을 누르면 원문이 URL에 포함되어 Google에 전송되며 브라우저 방문 기록에도 남을 수 있습니다. 버튼을 누르기 전에는 앱이 Google 번역을 호출하지 않습니다.
